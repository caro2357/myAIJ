# Multi-agent systems 相关工作扩充方案（通俗说明版）

现有 Multi-agent systems（MAS）工作大致可以分为五类。

| 大类 | 理解 | 与本文关系 |
|---|---|---|
| 战略逻辑 | 用逻辑语言说明“哪些智能体合作后能保证什么” | 是本文描述博弈能力的理论基础 |
| 形式化验证 | 给定系统和性质，检查系统是否满足性质 | 多数只做验证，不直接生成广义策略 |
| 策略合成与表示 | 从目标出发自动算出策略，并考虑策略如何表示 | 与本文最接近 |
| 协调与分布式优化 | 让多个智能体分工、协商或共同优化 | 能说明“规则设计”，但通常不是对抗性必胜策略 |
| 规划与学习 | 在不确定环境中规划或通过交互学策略 | 通常缺少本文要求的精确形式化保证 |

## 二、战略推理的逻辑与语义基础

### 2.1 联盟能力与战略逻辑

这一小类首先解决“怎样用逻辑准确描述策略能力”。它通常负责表达问题，而不负责高效地求出策略。

#### 1. A Modal Logic for Coalitional Power in Games

- **作者与年份：** Marc Pauly，2002
- **它解决什么：** 表达“某个联盟联合行动后，能够保证哪些结果”。
- **方法说明：** 论文把一个联盟看成整体，并用模态算子描述它能强制实现的结果。与普通模态逻辑只问“结果是否可能”不同，它进一步问“哪个联盟有能力让结果发生”。
- **局限：** 它主要描述一次选择后的结果，不擅长表达“始终安全”“最终获胜”这类跨越多步的目标，也没有把策略本身当作可操作对象。

#### 2. Alternating-Time Temporal Logic ✅

- **作者与年份：** Rajeev Alur、Thomas A. Henzinger、Orna Kupferman，2002
- **它解决什么：** 传统 LTL 和 CTL 量化的是系统中可能出现的路径，却不区分路径由谁控制。在开放系统或多智能体系统中，下一步通常由多个参与者共同决定，因此只问“是否存在一条到达目标的路径”并不能说明某个联盟是否真正有能力实现目标。ATL 解决的正是这个问题：给定一个联盟和时间目标，判断该联盟能否在其余智能体任意应对的情况下，保证下一步、最终到达、始终安全或持续满足某个性质。
- **方法说明：** ATL 以并发博弈结构（concurrent game structure）为语义模型。每个状态下，每个智能体同时选择一个动作，联合动作共同决定后继状态。联盟算子 ⟨⟨A⟩⟩ 表示联盟 A 存在一个联合策略，使所有与该策略相容的执行都满足后面的时间目标。模型检测采用自底向上的集合计算：先用联盟前驱算子找出“联盟一步内能够强制进入目标集合”的状态，再通过最小或最大固定点反复扩展，得到可达性、安全性和持续性目标的满足状态。对不带公平约束的 ATL，这一过程可以在线性时间内完成，并可由 CTL 的符号模型检测算法自然扩展而来。
- **与 AIJ 本文的关系：** ATL 提供了“联盟能够保证目标”的标准语义，也把模型检测与获胜区域计算联系起来；本文进一步要求在无限状态 ICG 上给出精确获胜公式和可直接执行的算术规则策略。
- **局限：** ATL 只说某种策略存在，却不把策略作为显式对象给出来，因此不方便比较、共享或再次量化不同策略。在不完备信息和完美记忆同时存在时，一般模型检测甚至不可判定。

#### 3. Cooperation, Knowledge, and Time: Alternating-Time Temporal Epistemic Logic and Its Applications

- **作者与年份：** Wiebe van der Hoek、Michael Wooldridge，2003
- **它解决什么：** 同时表达联盟能力、时间变化和智能体知识。
- **方法说明：** ATEL 在 ATL 上加入“智能体知道什么”的算子，因此可以区分“联盟实际上能完成任务”和“联盟知道自己能完成任务”。这适合每个智能体只能看到局部信息的系统。
- **局限：** 知识、时间和策略放在一起后，语义和计算都会明显变复杂。实际算法往往必须限制观察方式、记忆长度或允许的策略类型。

#### 4. Strategy Logic ✅

- **作者与年份：** Krishnendu Chatterjee、Thomas A. Henzinger、Nir Piterman，2010
- **它解决什么：** ATL 可以判断联盟是否“存在某种策略”，但量词结束后无法继续引用这项策略，因此难以表达两个玩家是否使用同一策略、某个玩家改变策略后会发生什么。Strategy Logic 让策略成为显式的一阶对象，使逻辑能够描述策略之间的依赖、共享、比较和偏离。这对非零和博弈尤其重要，因为这类博弈关心的不只是某方能否获胜，还关心多个玩家的策略组合是否稳定。
- **方法说明：** 论文引入策略变量及其存在、全称量词，并把量化后的策略绑定给具体玩家。公式可以先选择策略 x，再指定某个玩家采用 x，随后在同一公式中继续讨论该策略产生的执行。其 one-alternation 片段已经能够表达 Nash equilibrium 和 secure equilibrium 的存在性，并涵盖 ATL、ATL* 等已有战略逻辑的多种性质。判定过程把满足某个公式的策略赋值编码为树，再构造树自动机识别这些赋值；策略量词的交替对应自动机操作和非空性检查。这样得到的是一个统一的显式策略推理框架，而不是只针对某一种均衡写专门算法。
- **与 AIJ 本文的关系：** 该工作说明“策略本身”可以成为自动推理和输出对象，为本文从获胜状态集合进一步生成广义获胜策略提供逻辑层面的参照。
- **局限：** 表达能力越强，求解代价越高。完整逻辑的计算复杂度很高，实际工具通常只能处理受限片段或较小的有限模型。

### 2.2 复杂度边界

这一小类回答“为什么有些看起来合理的问题实际上算不出来”。

#### 5. Model-Checking ATL under Imperfect Information and Perfect Recall Semantics Is Undecidable

- **作者与年份：** Cătălin Dima、Ferucio Laurențiu Țiplea，2011
- **它解决什么：** 证明某类 ATL 验证问题不存在通用终止算法。
- **方法说明：** 当智能体只能看到局部信息，却可以记住无限长历史时，论文证明一般 ATL 模型检测不可判定。也就是说，不可能设计一个对所有此类输入都能结束并给出正确答案的算法。
- **局限：** 这是一个“不可能性”结论，只解释边界，不提供实际求解策略。

#### 6. Reasoning About Strategies: On the Model-Checking Problem

- **作者与年份：** Fabio Mogavero、Aniello Murano、Giuseppe Perelli、Moshe Y. Vardi，2014
- **它解决什么：** 系统分析更强 Strategy Logic 及其可计算片段。
- **方法说明：** 论文研究策略量词怎样嵌套、策略怎样绑定给智能体，并给出 SL[NG]、SL[BG] 和 SL[1G] 等片段。核心思想是在表达能力和可计算性之间寻找可用的平衡点。
- **局限：** 完整 Strategy Logic 的模型检测具有非初等复杂度；即使换成受限片段，自动机转换和博弈求解仍可能造成很大的状态空间。

## 三、多智能体系统的形式化验证

### 3.1 Abstraction–refinement：先简化，再逐步补细节

这类方法先把许多具体状态合并成少量抽象状态。如果抽象模型已经能证明性质，就直接结束；如果结果是“未知”或反例是假的，再把相关部分拆得更细。

它与AIJ本文的共同点是都有迭代改进过程，但目标不同：abstraction–refinement 主要是为了把验证模型做小；本文则要发现适用于无限多个状态的精确获胜公式和显式规则策略。

#### 7. Counterexample-Guided Abstraction Refinement

- **作者与年份：** Edmund M. Clarke、Orna Grumberg、Somesh Jha、Yuan Lu、Helmut Veith，2000
- **它解决什么：** 用反例指导抽象模型逐步增加必要细节。
- **方法说明：** CEGAR 先在粗糙模型上检查性质。若得到反例，就回到原模型判断反例是否真的可执行；若反例是抽象造成的假象，就根据它加入新的区分条件，然后重新检查。
- **局限：** 它是通用验证框架，不专门处理联盟策略或知识。精化快慢高度依赖初始抽象和反例质量，最坏情况下可能不断加细，接近直接分析原模型。

#### 8. An Abstraction-Refinement Framework for Multi-Agent Systems ✅

- **作者与年份：** Thomas Ball、Orna Kupferman，2006
- **它解决什么：** 普通抽象方法通常只需近似“系统可能怎样运行”，但多人博弈还必须保存“哪一个智能体能够迫使哪一步发生”。如果只把具体状态简单合并，抽象模型可能夸大某个联盟的能力，也可能错误地削弱它的能力。该论文解决的问题是：怎样在缩小多人博弈状态空间的同时，可靠地验证不同联盟的战略能力，并在抽象过粗时自动增加必要细节。
- **方法说明：** 论文用抽象交替转移系统（abstract alternating transition system，AATS）表示博弈。对每个智能体，抽象模型同时保存 over-approximation 和 under-approximation：前者描述“可能可用”的能力，后者描述“确定可用”的能力。基于这两类转移，alternating μ-calculus 公式采用真、假、未知三值语义；真和假可以安全地传回具体系统，未知则说明当前抽象不足。框架还定义了按智能体集合参数化的抽象精度关系，并在出现未知结果时分析抽象证明或反例，拆分相关抽象状态。对于谓词抽象，新增区分条件还可以交给定理证明器检查和生成。
- **与 AIJ 本文的关系：** 它是多智能体 abstraction–refinement 的代表：两者都有“求解—发现不足—增加信息”的循环，但该工作精化的是验证模型，本文归纳的是无限状态获胜公式及条件—动作策略。
- **局限：** 在无限状态系统上，精化不一定停止；构造抽象转移还可能需要定理证明器。最终输出仍是验证结论和抽象模型，不是本文所需的算术条件—动作规则。

#### 9. Verification of Multi-Agent Systems via Predicate Abstraction against ATLK Specifications

- **作者与年份：** Alessio Lomuscio、Jakub Michaliszyn，2016
- **它解决什么：** 用有限个布尔谓词表示含无限数据域的多智能体系统。
- **方法说明：** 方法不枚举每个整数取值，而只记录若干谓词是否成立，例如“x 大于 0”。这样可以把无限数据状态压缩成有限布尔组合，再交给 BDD 和 SMT 求解。
- **局限：** 方法可靠但不完备，可能只能回答“未知”。选哪些谓词直接决定效果，而且原工作中的自动精化并不完整，抽象构造有时比最后的模型检测更耗时。

#### 10. Agent-Based Refinement for Predicate Abstraction of Multi-Agent Systems

- **作者与年份：** Francesco Belardinelli、Alessio Lomuscio、Jakub Michaliszyn，2016
- **它解决什么：** 当谓词抽象得到“未知”时，自动找出应该为哪个智能体增加什么谓词。
- **方法说明：** 算法定位造成不确定结果的 failure state 或 failure pair，再用 SMT 和 Craig 插值生成新谓词，只精化真正相关的智能体部分。
- **局限：** 插值结果和精化位置不唯一，效果依赖启发式；对无限状态问题仍不能保证最后得到真或假。

#### 11. An Abstraction-Refinement Framework for Verifying Strategic Properties in Multi-Agent Systems with Imperfect Information

- **作者与年份：** Francesco Belardinelli、Angelo Ferrando、Vadim Malvone，2023
- **它解决什么：** 在不完备信息和完美记忆造成不可判定时，仍尽量给出可靠结论。
- **方法说明：** 方法用一个完备信息的抽象博弈近似原系统，并用三值 ATL/ATL* 判断性质。若结果未知，就借助 LTL 自动机找出需要精化的状态。
- **局限：** 它只能保证已经给出的真或假不会错，却不能保证一定摆脱“未知”；当前还主要处理战略算子使用同一固定联盟的公式。

### 3.2 BDD/SAT 符号模型检测：不逐个列状态，而是整体编码

这类方法把许多状态和转移压进布尔公式、BDD 或 SAT/SMT 约束中。它可以减少显式枚举，但并没有消除状态爆炸，只是换了一种更紧凑的表示和搜索方式。

#### 12. Bounded Model Checking for Knowledge and Real Time

- **作者与年份：** Alessio Lomuscio、Wojciech Penczek、Bożena Woźna，2007
- **它解决什么：** 用 SAT 在给定步数内寻找违反知识或实时性质的执行。
- **方法说明：** 方法把前 k 步的状态、时间和知识关系展开成一个 SAT 公式。如果公式可满足，就得到长度不超过 k 的反例或见证。
- **局限：** 没找到反例只说明给定深度内没有，不自动等于所有深度都安全；k 增大后 SAT 编码也会迅速变大，而且它不输出广义策略。

#### 13. MCMAS: A Model Checker for the Verification of Multi-Agent Systems ✅

- **作者与年份：** Alessio Lomuscio、Hongyang Qu、Franco Raimondi，2009
- **它解决什么：** 多智能体系统不仅有普通的时间行为，还涉及“某个智能体知道什么”“某个联盟能保证什么”以及系统是否遵守特定规范。若把所有智能体的局部状态和动作显式组合，全局状态数会快速增长。MCMAS 提供一套可执行的建模和验证工具，让用户在同一模型上自动检查时间、知识、规范和战略性质，而不必为每种逻辑分别实现求解器。
- **方法说明：** 用户用 Interpreted Systems Programming Language（ISPL）分别定义每个智能体的局部状态、动作集合、协议条件和演化规则，再给出初始状态、命题赋值和待验证公式。工具把各智能体的局部规则组合成全局 interpreted system，并用有序二叉决策图（OBDD）符号表示可达状态、全局转移关系和智能体之间的不可区分关系。时间和战略算子通过前驱与固定点运算求值，知识算子则通过不可区分状态集合计算。除返回性质真假外，MCMAS 还能针对多类性质生成反例或见证执行，并支持公平性条件。
- **与 AIJ 本文的关系：** MCMAS 代表“给定有限模型后进行统一符号验证”的成熟路线；本文的重点则是从无限算术状态空间中归纳获胜区域并生成可读的广义策略。
- **局限：** 基础工具仍要求系统可以有限编码。BDD 是否紧凑很依赖变量编码和排序，也无法绕开某些语义本身的不可判定性。它主要验证性质，基础版本并不输出本文这种算术广义策略。

#### 14. Symbolic Model Checking Epistemic Strategy Logic

- **作者与年份：** Xiaowei Huang、Ron van der Meyden，2014

- **它解决什么：** 在符号模型中同时表示状态、观察和策略。

- **方法说明：** 方法把“在某种观察下选择哪个动作”也编码为布尔变量，从而一次性搜索多个候选策略，而不是逐个显式枚举。

- **局限：** 为保持可计算性，它主要采用只依赖当前观察的无记忆策略；观察数量和策略量词增加后，布尔变量仍会快速增长。

## 四、策略合成、博弈求解与策略表示

这一大类与本文最接近，因为它不只问性质是否成立，还要真正算出一个策略。不过，大多数方法仍然从有限状态博弈出发，输出有限状态控制器或状态—动作表。

### 4.1 从时序目标直接合成策略与均衡

#### 15. Synthesis of Reactive(1) Designs ✅

- **作者与年份：** Roderick Bloem、Barbara Jobstmann、Nir Piterman、Amir Pnueli、Yaniv Sa'ar，2012
- **它解决什么：** 一般 LTL synthesis 要从时间逻辑规范直接构造一个面对所有环境行为都正确的系统，最坏情况下需要双指数时间，难以处理实际设计。很多硬件和反应式控制规范却具有较规整的 assume–guarantee 结构：只要环境持续满足若干假设，系统就必须持续兑现若干保证。该论文研究怎样利用这种常见结构，在保持形式化正确性保证的同时，大幅降低可实现性检查和策略生成的计算代价。
- **方法说明：** 方法把环境和系统看成在有限状态图上交替选择输入、输出的两方博弈。GR(1) 规范包含初始条件、限制每一步变化的安全条件，以及形如“环境的若干公平条件反复成立，则系统的若干公平目标也反复成立”的活性条件。求解器通过嵌套固定点和秩计算得到系统的获胜区域，核心符号步骤相对于博弈状态数是二次的。若初始状态位于获胜区域内，算法再根据固定点计算留下的选择抽取有限状态策略，并可进一步删减状态或优化策略。论文还用总线仲裁器案例展示了从规范、可实现性判断到硬件实现抽取的完整过程。
- **与 AIJ 本文的关系：** GR(1) 与本文都先计算获胜区域、再从中抽取策略；主要区别是 GR(1) 处理有限布尔状态和受限 LTL 规范，而本文希望把无限整数状态压缩成精确算术公式和规则。
- **局限：** 它只覆盖 GR(1) 这一受限规范类别，基本算法也面向有限布尔状态。输出通常是有限状态控制器，不是无限整数状态上的算术规则。

#### 16. Verifying and Synthesising Multi-Agent Systems against One-Goal Strategy Logic Specifications ✅

- **作者与年份：** Petr Čermák、Alessio Lomuscio、Aniello Murano，2015

- **它解决什么：** 完整 Strategy Logic 可以表达复杂的策略依赖和量词交替，但计算代价过高，难以直接做成实用验证器。ATL* 的计算性质较好，却不能自然表达多个显式策略变量之间的依赖。该论文选择 One-Goal Strategy Logic（SL[1G]）作为折中：在保留策略量化和智能体绑定能力的同时，把每个量化—绑定前缀限制为服务于一个时间目标，并同时解决公式验证和见证策略生成问题。

- **方法说明：** 输入是一个 interpreted system、初始状态和 SL[1G] 公式。公式先被分解为策略量化前缀、智能体绑定前缀和底层 LTL 目标；LTL 目标被转换成确定性奇偶自动机。随后，算法构造一个两方公式竞技场，让两方按照存在或全称策略量词的顺序选择动作，从而显式保持策略变量之间应有的依赖与独立性。公式竞技场与奇偶自动机组合成奇偶博弈，求解其获胜区域即可判断公式真假，获胜策略则给出被存在量化策略变量的具体实现。论文进一步把竞技场、自动机和求解过程编码为 BDD，并在 MCMAS-SL[1G] 原型中实现和测试。

- **与 AIJ 本文的关系：** 该工作比普通模型检测更接近本文，因为它会真正抽取策略；但其策略仍依附于有限 interpreted system 和自动机构造，不会归纳成覆盖无限整数状态的算术规则。

- **局限：** SL[1G] 是完整 Strategy Logic 的受限片段；自动机确定化和奇偶博弈会随智能体、目标和公式规模快速膨胀，并且仍以有限模型为基础。

#### 17. Rational Synthesis ✅

- **作者与年份：** Dana Fisman、Orna Kupferman、Yoad Lustig，2010
- **它解决什么：** 传统 reactive synthesis 把环境看成能够任意行动的敌手，要求系统在所有环境行为下都满足规范。这种最坏情况假设在安全关键场景中合理，但当环境由多个有自身目标的智能体组成时会过于保守：这些智能体通常不会为了破坏系统而选择一个同时损害自身目标的行为。Rational Synthesis 研究怎样利用智能体的理性假设，在保证系统目标的同时，为各环境智能体安排它们愿意遵守的策略。
- **方法说明：** 输入包括系统的时序逻辑规范、每个环境智能体各自的时序目标，以及用于解释“没有偏离动机”的 solution concept。输出不只是系统实现，还包括建议给所有智能体的一组策略。该结果必须同时满足两个条件：这些策略共同执行时，系统规范成立；对每个环境智能体而言，按照所选的 dominant-strategy、Nash-equilibrium 或相关均衡概念，它都不能通过允许的单方面偏离更好地实现自己的目标。求解方法把各方的时间目标转换为自动机条件，并在合成过程中检查候选策略组合及其偏离行为。论文还讨论了目标取有限格值的多值扩展，并表明对经典均衡概念，rational synthesis 的最坏复杂度不高于传统时序合成。
- **与 AIJ 本文的关系：** 它说明多智能体策略合成可以改变对环境的行为假设；本文采用的是两人零和 ICG 的最坏对手语义，因此不依赖理性或均衡假设，保证含义更接近传统必胜策略。
- **局限：** 结果依赖所选均衡概念和理性假设；有限状态自动机、时序逻辑和均衡推理组合后计算代价很高。它与本文两人零和、对最坏对手保证获胜的语义也不相同。
- **推荐理由：** TACAS 经典工作，开辟了“不是把所有其他智能体都当成任意敌手”的多智能体合成路线。

#### 18. Automated Temporal Equilibrium Analysis: Verification and Synthesis of Multi-Player Games ✅

- **作者与年份：** Julian Gutierrez、Muhammad Najib、Giuseppe Perelli、Michael Wooldridge，2020
- **它解决什么：** Rational Synthesis 提出了理性环境下的合成问题，但还需要能够实际分析多人系统的工具。该论文关注 temporal equilibrium analysis：当每个玩家都追求自己的长期 LTL 目标并选择 Nash-equilibrium 策略时，系统是否存在均衡、哪些时间性质会在部分或全部均衡执行上成立，以及怎样生成实现这些均衡的玩家策略。
- **方法说明：** EVE 的输入分成三部分：用 Simple Reactive Modules Language（SRML）描述的并发系统、每个玩家希望满足的 LTL 目标，以及一个待检查的 LTL 系统性质。核心算法把均衡存在性和均衡路径性质归约为一组奇偶博弈。归约不仅检查候选执行是否满足各玩家目标，还要为每个玩家构造“单方面偏离”检查，排除能够通过改变自身策略改善结果的候选策略组合。求解这些奇偶博弈后，EVE 可以回答系统是否存在 Nash equilibrium、给定性质是否在某个或所有均衡执行上成立，并从获胜解中提取各玩家的有限状态策略。论文还要求均衡分析在双模拟等价模型下保持不变，从而避免结果依赖无关的建模细节。
- **与 AIJ 本文的关系：** EVE 展示了从多人时序模型中同时做验证和策略抽取的完整工具链；本文处理的博弈语义更简单，但状态空间是无限的，输出还必须是全状态可解释的算术规则。
- **局限：** 方法主要处理有限并发博弈和纯策略；LTL 自动机与奇偶博弈的组合会造成明显的状态增长。

### 4.2 可解释的策略求解与表示

这一小类关心两个问题：能否保留全部安全选择，以及能否把庞大策略压缩成人容易检查的规则。它与本文的“获胜且穷尽的条件—动作规则集合”关系最直接。

#### 19. Permissive Strategies: From Parity Games to Safety Games ✅

- **作者与年份：** Julien Bernet、David Janin、Igor Walukiewicz，2002
- **它解决什么：** 传统博弈求解器通常只返回一个获胜策略，但同一状态可能存在多个同样安全的获胜动作。任意选其中一个会过早丢弃其他正确行为，使控制器缺乏适应后续约束、优化目标或实现变化的余地。论文因此不再只比较策略是否获胜，而是按照策略所允许的行为集合比较策略，希望得到一个在保证获胜的前提下尽量宽松的策略。
- **方法说明：** 论文把 permissive strategy 理解为可以在同一历史下保留多个动作的非确定性策略。它首先指出：若考虑全部获胜策略，不一定存在一个能够包含所有获胜行为的最大元素；但对 parity game 的全部无记忆获胜策略，总能构造一个覆盖其所有行为的 permissive strategy。算法把原 parity game 连同进展信息转换为 safety game，使违反奇偶获胜条件的长期风险变成必须避开的坏状态；在 safety game 上计算最大获胜区域和所有安全选择后，再映射回原博弈。所得策略允许所有由无记忆获胜策略产生的行为，其求解复杂度与当时计算 parity game 获胜区域的已知上界相同。
- **与 AIJ 本文的关系：** 它与本文“获胜且穷尽”的目标最接近：两者都希望保留一类正确动作，而不是任意给出一个动作；区别在于该工作枚举有限博弈中的允许行为，本文要用算术条件概括无限多个状态。
- **局限：** 方法针对有限 parity game 和无记忆策略。输出仍是有限博弈中的允许行为结构，并不会自动归纳成适用于无限整数状态的算术条件。

#### 20. Strategy Representation by Decision Trees in Reactive Synthesis ✅

- **作者与年份：** Tomáš Brázdil、Krishnendu Chatterjee、Jan Křetínský、Viktor Toman，2018
- **它解决什么：** 反应式合成工具可以生成正确策略，但策略往往以状态—动作表或 BDD 保存。这样的表示适合机器执行，却难以让人看出“满足什么条件时选择什么动作”，BDD 的最小化和解释也不直接对应原模型中的决策含义。该论文研究怎样在不牺牲任何正确性的前提下，把完整策略改写成较小、可阅读的决策树。
- **方法说明：** 输入是有限图博弈上的一个已验证策略，以及描述状态的布尔或离散特征。每个树叶给出相应状态区域内允许的动作，内部节点则用某个状态特征把策略样本分开。算法借鉴决策树学习中的熵和信息增益来选择划分，使具有相同动作选择的状态尽量聚到一起；但它不允许普通分类学习中的近似误差，生成的树必须在每个相关状态上与某个获胜动作一致。对于原策略允许多个动作的情况，构树过程还可以在保持获胜性的前提下选择更利于压缩的动作。论文在 reactive synthesis 基准上比较决策树与 BDD，说明决策树通常能更直接地呈现策略的条件结构。
- **与 AIJ 本文的关系：** 该工作展示了“条件测试—动作叶节点”是一种可解释的策略表示；本文进一步把条件限制为可证明正确的算术公式，并把表示学习与无限状态获胜区域发现放在同一合成过程中。
- **局限：** 决策树主要是已有策略的表示和压缩工具，不能自己发现无限状态获胜区域。树是否简洁还依赖输入特征是否合适。

### 4.3 不完备信息下的直接战略验证与合成

#### 21. STV: Model Checking for Strategies under Imperfect Information

- **作者与年份：** Damian Kurpiewski、Wojciech Jamroga、Michał Knapik，2019
- **它解决什么：** 在智能体只能看到部分状态时搜索并检查策略。
- **方法说明：** STV 实现多种策略搜索算法，判断不完备信息下某个联盟能否保证时序目标，并在成功时给出策略。
- **局限：** 基础版本主要处理有限模型和无记忆策略，部分算法仍要探索很大的策略空间。

### 4.4 多目标智能体

#### 22. PRISM-games: Verification and Strategy Synthesis for Stochastic Multi-Player Games with Multiple Objectives ✅

- **作者与年份：** Marta Kwiatkowska、David Parker、Clemens Wiltsche，2018
- **它解决什么：** 许多多智能体系统既包含合作或竞争决策，也包含故障、噪声、随机延迟等概率行为。普通 ATL 或确定性博弈只能回答某个目标是否能够被保证，无法表达“达到目标的概率至少为多少”“期望代价是否低于阈值”或多个概率、奖励目标之间的取舍。PRISM-games 为这类定量问题提供统一的建模、验证和策略合成工具。
- **方法说明：** 论文以有限的轮流行动随机多人博弈为主要模型：当前状态由某个玩家选择动作，动作执行后再按概率分布进入下一状态。性质使用带奖励的概率交替时序逻辑 rPATL 表达，可以量化联盟实现概率或奖励目标的能力。模型检测把一个联盟与其余玩家合并为随机两方博弈，再通过数值固定点、值迭代等算法计算最优概率或期望奖励，并抽取达到这些值的策略。对于多个目标，工具计算可达的 Pareto 权衡，回答是否存在一个策略同时满足多个界限；其 compositional 方法还可用 assume–guarantee 形式组合子系统分析。最终输出包括性质真假、定量值、Pareto 信息以及可导出的玩家策略。
- **与 AIJ 本文的关系：** PRISM-games 说明多智能体策略合成可以同时处理概率和多个优化目标；本文追求的是无随机性的精确必胜保证，因此输出是逻辑公式和规则，而不是概率值或数值近似策略。
- **局限：** 该版本主要面向有限、轮流行动的随机多人博弈。多目标 Pareto 计算和数值迭代会随状态数、玩家数和目标数快速变重，输出也不是精确算术广义策略。

## 五、多智能体协调与分布式优化

这一类主要研究“多个智能体怎样合作完成任务”，不一定存在明确对手，也不一定追求必胜保证。

### 5.1 任务分配、协商与社会规则

#### 23. The Contract Net Protocol: High-Level Communication and Control in a Distributed Problem Solver

- **作者与年份：** Reid G. Smith，1980
- **它解决什么：** 在分布式节点之间动态分配任务。
- **方法说明：** 一个节点发布任务，其他节点根据自己的能力投标，发布者再授予合同并收集结果。这成为后来多智能体协商和任务分配协议的经典原型。
- **局限：** 协议主要保证任务能够被协商分配，不保证一般情况下的全局最优，也不计算时序逻辑或博弈意义下的获胜策略。

#### 24. On Social Laws for Artificial Agent Societies: Off-Line Design ✅

- **作者与年份：** Yoav Shoham、Moshe Tennenholtz，1995
- **它解决什么：** 多个自主智能体各自按照局部目标行动时，即使单个智能体的行为合理，组合起来仍可能发生冲突、死锁或相互阻塞。逐次在线协商会增加通信和决策负担。该论文研究能否在系统运行前就设计一套所有智能体共同遵守的 social law，用少量动作限制排除有害交互，同时保留足够自由，使每个智能体仍能完成自己的任务。
- **方法说明：** social law 被形式化为与状态条件相关的动作限制，可以理解为“在满足条件 c 时禁止执行动作 a”。设计者先分析智能体可能的局部行为和交互，再离线选择一组限制；运行时每个智能体只需在剩余合法动作中独立规划，不需要中央控制器逐步指定联合动作。论文先以移动机器人协调说明交通方向、让行等规则如何避免碰撞，再给出一般计算模型，定义什么样的规则是 useful social law，并研究自动判断和合成这类规则的计算问题。方法的输出是一套对所有参与者生效的约束，而不是每个状态下唯一指定的联合计划。
- **与 AIJ 本文的关系：** social law 与本文都产生“条件—动作”形式的规则，但前者通过禁止动作改善群体共存，后者必须为当前玩家给出覆盖全部获胜状态、能够对抗任意对手行为的获胜动作。
- **局限：** 一般社会规则设计计算困难，论文主要讨论有限计算模型和受限情形。社会规则让整个系统更协调，却不等同于两人零和博弈中的精确必胜策略。

### 5.2 分布式优化

#### 25. ADOPT: Asynchronous Distributed Constraint Optimization with Quality Guarantees

- **作者与年份：** Pragnesh Jay Modi、Wei-Min Shen、Milind Tambe、Makoto Yokoo，2005
- **它解决什么：** 让多个智能体在不集中暴露全部信息的情况下找到全局最优联合选择。
- **方法说明：** ADOPT 让智能体异步交换代价上下界，并不断修改自己的局部取值。只要搜索完成，就能保证全局最优，也可以提前停止并给出有质量界的近似结果。
- **局限：** 最坏情况下搜索和通信仍呈指数增长；它处理的是有限离散协作优化，不是对抗博弈中的必胜策略。

#### 26. A Scalable Method for Multiagent Constraint Optimization

- **作者与年份：** Adrian Petcu、Boi Faltings，2005
- **它解决什么：** 用较少通信轮次完成分布式约束优化。
- **方法说明：** DPOP 把约束图整理成伪树，自底向上传递效用表，再自顶向下确定每个智能体的取值。消息数量较少，但每条消息可能很大。
- **局限：** 消息大小对伪树的 induced width 呈指数增长，可能造成严重内存压力；方法仍假设有限变量和共同优化目标。

### 5.3 多个智能体各自只看到局部信息

#### 27. The Complexity of Decentralized Control of Markov Decision Processes

- **作者与年份：** Daniel S. Bernstein、Robert Givan、Neil Immerman、Shlomo Zilberstein，2002
- **它解决什么：** 建立 Dec-MDP/Dec-POMDP 的正式模型并说明其计算难度。
- **方法说明：** 多个智能体各自收到局部观察、分别选动作，但共同影响状态和奖励。论文证明，即使只有两个智能体，有限时域 Dec-POMDP 也达到 NEXP 级困难。
- **局限：** 它主要给出模型和复杂度下界，不是一套直接输出策略的实用算法。

#### 28. MAA*: A Heuristic Search Algorithm for Solving Decentralized POMDPs

- **作者与年份：** Daniel Szer、François Charpillet、Shlomo Zilberstein，2005
- **它解决什么：** 在有限时域 Dec-POMDP 中搜索最优联合策略。
- **方法说明：** MAA* 把 A* 搜索用于多个智能体的联合策略树，用启发式上界判断哪些部分策略更有希望，并优先扩展它们。
- **局限：** 联合策略树会随时域、观察数和智能体数急剧增长，通常只能处理较小问题。

现有多智能体研究已经形成从性质表达、模型验证到策略生成和表示的多条技术路线。ATL 与 Strategy Logic 分别用于描述联盟的时序能力、知识以及显式策略之间的绑定和依赖，而相关复杂度研究进一步揭示了不完备信息、完美记忆和复杂策略量化所带来的不可判定性或高计算代价。在验证方面，abstraction–refinement、谓词抽象以及基于 BDD、SAT/SMT 的符号模型检测通过合并状态或整体编码状态空间来缓解状态爆炸；MCMAS 等工具已经能够统一检查时间、知识和战略性质，但抽象过粗时可能只能返回“未知”，符号表示的规模也仍受模型结构影响。在合成方面，GR(1) 和 SL[1G] 可以从时序或战略规范计算获胜区域并抽取有限状态策略，permissive strategy 尽量保留多个获胜动作，Strategy Representation by Decision Trees 则将已有策略压缩为较易检查的条件—动作结构。Rational Synthesis 和 EVE 将理性假设与 Nash equilibrium 纳入多智能体策略合成，PRISM-games 进一步处理多目标智能体的复杂情况；Social Laws则从共同动作限制的角度处理智能体之间的协作与决策。这些方法覆盖的目标和语义十分广泛，但通常依赖有限状态博弈、受限时序规范、预先给定的抽象谓词或已经生成的有限控制器，难以直接归纳适用于无限多个整数状态的精确获胜条件及完整规则。
